# TBFactory product context

## Register

product

## Users

Developers reviewing pull requests and installation operators configuring a shared
Factory. The first real-provider walkthrough serves the existing User with an
Azure DevOps account. Work is performed in a browser on a desktop or laptop;
narrow screens and keyboard navigation must remain usable.

## Product Purpose

Make a pull request Review understandable from intake through the private report,
human Review Decision, explicit publication, and separate Work Item finalization.
The Kanban Board summarizes work; the Work Item detail contains its actions and
evidence. Administration has its own view.

## Brand Personality

Clear, calm, practical. Preserve the existing light interface and green accent.
The User approved this direction on 2026-10-08 after inspecting the current MVP.

## Anti-references

Avoid the current wall of forms, reports embedded in Kanban cards, nested panels,
and cards taller than the screen. Avoid decorative dashboards or a new visual
identity unrelated to the existing application.

## Design Principles

- Show the work overview before its controls.
- Open one Work Item to review its evidence and act on it.
- Keep Factory state distinct from Workflow Run execution state.
- Preserve authorization, retained versions, and explicit human decisions.
- Explain the next step and any missing prerequisite where the User needs it.

## Accessibility and Inclusion

Use semantic navigation, visible keyboard focus, labeled native controls, readable
contrast, responsive layouts, and status text that does not rely on color alone.
Preserve existing English interface and repository documentation; guided
conversation may be in Spanish.
