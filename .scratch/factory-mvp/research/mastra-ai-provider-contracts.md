# Mastra AI provider contracts

Status: evidence for [Establish Mastra AI provider configuration constraints](../issues/13-mastra-ai-provider-contracts.md). Checked 2026-10-04. Current documentation describes the mutable current release; pinned evidence below is specific to `@mastra/core` 1.74.0. The selected initial platform route remains OpenRouter with GPT-6 Luna as recorded in the [local design](../designs/durable-private-review-report.md); this research does not verify that model's availability.

## Current documentation

Mastra documents a built-in model router covering provider/model IDs, including provider gateways such as OpenRouter, and direct use of AI SDK provider modules. Router IDs use provider environment keys by default. Its current docs also show dynamic model choice for multi-tenant applications. A custom `url` on Mastra's router is specifically an OpenAI-compatible endpoint: Chat Completions is the default wire API, with Responses selectable. Therefore, custom URL support is protocol-specific; it is not evidence that every provider protocol can be configured through one generic URL field. [Model providers and custom endpoints](https://mastra.ai/models)

## Checked `@mastra/core` 1.74.0 evidence

The prototype lockfile selects `@mastra/core` 1.74.0 and records the npm tarball integrity. The official Mastra tag `@mastra/core@1.74.0` resolves to source commit [`b21e46e`](https://github.com/mastra-ai/mastra/tree/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core). Its `MastraModelConfig` accepts router model IDs, AI SDK LanguageModel versions 1–4, and an `OpenAICompatibleConfig`. That config has `apiKey`, `url`, `headers`, and `api: 'chat' | 'responses'`; API key is optional and can fall back to environment variables. The agent model can be resolved dynamically from `requestContext`, and `generate()` accepts a per-call model override. These types establish several integration forms, not an OpenAI-compatible-only restriction. [Pinned model types](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/llm/model/shared.types.ts), [pinned dynamic model resolution](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/agent/agent.ts), [prototype lockfile](../../../prototypes/durable-workflow-storage/package-lock.json)

For Organization isolation, construct or resolve the selected model using that Organization's stored key at dispatch time and pass it explicitly through an adapter or model configuration. Never rely on the optional environment fallback for Organization credentials and never mutate process-wide environment variables. Mastra does not provide the Factory's secret vault or enforce Organization isolation; those remain application responsibilities. For non-OpenAI-compatible providers, use an explicitly supported native provider adapter/model instance with its provider-specific configuration. An arbitrary URL/protocol is not made supported by `MastraModelConfig` alone.

The pinned call API accepts provider options and model settings. Provider options are adapter-specific (the 1.74.0 types include OpenAI, Azure, Anthropic, Google, DeepSeek, and xAI namespaces); reasoning effort is not a universal setting. The pinned `modelSettings.reasoning` field is effective only for supporting AI SDK v7/LanguageModelV4 providers and is a no-op with V2/V3. [Pinned provider options](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/llm/model/provider-options.ts), [pinned model settings and timeouts](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/llm/model/model-settings.ts)

Mastra agents support application-defined tools and schema-based structured output. `generate()` returns token usage and per-step usage. Native structured output uses the provider's response-format capabilities; Mastra warns that some model APIs cannot combine native structured output and tools. The documented choices are prompt-injected schema, separate structuring model, or separate steps. A second structuring model is an additional model call and must count against limits. Validate reports independently in Factory code. [Agents and tool use](https://mastra.ai/docs/agents/overview), [structured output constraints](https://mastra.ai/docs/agents/structured-output), [current generation reference](https://mastra.ai/reference/agents/generate)

## Supported boundary and budget implications

Source-supported proposal: expose a platform-owned allowlist of provider adapters. An Organization chooses an adapter and permitted model, supplies its API key, and supplies an endpoint only where that adapter supports one. Keep URL semantics, reasoning controls, tool support, structured-output support, usage fields, and cancellation behavior tied to each adapter/model capability. Platform-owned AI and Organization-owned AI can share this boundary while resolving different credentials. Do not allow fallback models unless explicitly selected and recorded.

Mastra 1.74.0 accepts `AbortSignal`; its reference describes aborting ongoing work, including delegated subagent runs. `modelSettings.timeout.stepMs` limits one wall-clock model call, while `totalMs` limits a full agent run including tools and retries. Neither implements the proposed sum of model-call durations across parent/subagents and concurrent calls while excluding tool time. Factory must account for each model dispatch itself, persist aggregate call time, and abort when its own limit is reached. An abort only records local cancellation; it does not prove the provider stopped processing or charging. Mastra also supports retries/fallback model lists, so disable implicit fallback for a fixed Organization selection and count any allowed retry as another dispatch. [Pinned call options](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/agent/agent.types.ts), [pinned timeout behavior](https://raw.githubusercontent.com/mastra-ai/mastra/b21e46e19b469a25c8896bcee90afd58d6f1a890/packages/core/src/llm/model/model-settings.ts)

Unresolved: the initial Organization adapter allowlist, which adapters support custom endpoints, model/provider capability validation, endpoint policy, and whether any native model supports both the required tools and structured output. These require implementation or model-specific checks; current docs do not settle them for the selected GPT-6 Luna route.
